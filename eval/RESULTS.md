# 추출 정밀도 측정 기록 (mock 추출기)

기준선: `BASELINE_before_tuning.jsonl` (이 라운드 수정 전 추출기, 수정한 정답셋 기준).
수정 후: `python -m mirror.eval_precision --protocol --extractor mock`

| 세트 | 모드 | 정밀도 전→후 | 재현율 전→후 |
|---|---|---|---|
| dev | strict | 0.471 → 0.400 | 0.444 → 0.444 |
| dev | scoped | 0.923 → 0.938 | 0.706 → 0.882 |
| tune | strict | 0.697 → 0.692 | 0.697 → 0.818 |
| tune | scoped | 0.893 → 0.970 | 0.758 → 0.970 |
| heldout | strict | 0.750 → 0.733 | 0.700 → 0.733 |
| heldout | scoped | 0.957 → 0.958 | 0.733 → 0.767 |

heldout에서 남은 오류(코드는 이 오류를 보고 고치지 않았다):
- 반복 단서 "항상", "늘"을 못 읽음 (h3, h4)
- 시간대 "밤"을 못 읽음 (h1)
- "개운했다"가 결과인데 조건으로 연결 (h5)
- strict 전용: 자유 서술 관계 RELATED_TO와 DERIVED_FROM이 정답셋에 없어서 오류로 집계

이 오류를 고치려면 새 heldout 세트를 만든 뒤 측정해야 한다. 이번 heldout은 이미 노출됐다.


## 2라운드 (기준선 `BASELINE_round2.jsonl` → `AFTER_round2.jsonl`)
수정은 dev·tune·tune2의 오류에서 나온 것만 했다. heldout2는 수정이 끝난 뒤 한 번 채점했다.

| 세트 | 모드 | 정밀도 | 재현율 |
|---|---|---|---|
| tune2 | scoped | 0.958 → 1.000 | 0.767 → 1.000 |
| **heldout2** | scoped | 0.892 → **0.933** | 0.767 → **0.977** |
| **heldout2** | strict | 0.696 → **0.685** | 0.744 → 0.861 |
| dev | scoped | 0.938 → 0.882 | 0.882 → 0.882 |

dev scoped가 내려간 이유는 "일요일 밤"에서 새로 잡힌 `ctx:밤`이 dev 정답셋에 없어서다. 본문에는 밤이 있으므로 정답셋 쪽 누락이다.


## 3라운드: 독립 작성 평가 세트 (heldout3, 16장면)
- 작성: 추출기 코드와 어휘를 보지 않은 별도 에이전트가 `GUIDELINE.md`만 읽고 문장과 정답을 썼다. 사용자 검토 전.
- 비교: 3라운드 수정 전 추출기(`extract_round2_snapshot.py.txt`)와 수정 후 추출기를, 두 버전 모두 확정된 뒤 이 세트에서 한 번 채점했다. 결과는 `RESULT_heldout3.json`.
- 3라운드 수정: 한 글자 장소("집")의 단어 경계, 선호 주어 판정(은/는 포함, 좋아 직전의 가장 가까운 주어).

| 모드 | 정밀도 | 재현율 |
|---|---|---|
| strict | 0.658 → 0.692 | 0.562 → 0.562 |
| scoped | 0.895 → 0.919 | 0.708 → 0.708 |

## 4라운드: 아무도 보지 않은 독립 세트 (heldout4, 20장면)
별도 에이전트가 작성. 세 버전을 수정 없이 한 번 채점했다. `extract_original_reconstructed.py.txt`는 이 세션 시작 시점 추출기를 복원한 것이고, dev에서 0.3182/0.3889를 그대로 재현해서 검증했다.

| 버전 | strict P / R | scoped P / R |
|---|---|---|
| 세션 시작 | 0.429 / 0.333 | 0.676 / 0.463 |
| 1라운드 전 | 0.450 / 0.333 | 0.714 / 0.463 |
| 지금 (채점 당시) | 0.408 / 0.370 | 0.705 / 0.574 |

- 정밀도는 독립 세트에서 오르지 않았다. 재현율만 올랐다.
- 2라운드에 넣은 반복 단서 "늘 "이 "오늘 처음"의 "오늘 "에 걸리는 회귀가 원인 하나였다. 내가 쓴 평가 세트는 이걸 못 잡았고 독립 세트가 잡았다.
- 이 회귀는 사후에 고쳤다(테스트 추가). 그래서 아래 "사후 수정 후" 수치는 heldout4를 본 뒤 고친 결과라서 깨끗한 측정이 아니다.

## 5라운드: 복합 장소명 규칙 (기각)
- 시도: 장소 어휘 앞의 명사 한 어절을 이름에 합친다("한강 공원", "보드게임 카페"). heldout4의 부분 일치 오류에서 나온 규칙이다.
- 기준: 노출된 모든 세트에서 손해가 없을 것(사전에 정함).
- 결과: heldout4는 scoped 정밀도 0.756 → 0.805로 올랐지만 tune 0.970 → 0.879, heldout2 0.977 → 0.954, heldout3 0.919 → 0.892로 내려갔다. 기준에 못 미쳐 되돌렸다.

## 7라운드: LLM 추출기(spark) 채점
규칙 추출기는 제품 경로의 기본값에서 뺐다(테스트 전용). 독립 세트 3개(heldout3~5, 60장면)에서 엔티티·맥락(OBSERVED_IN)만 같은 기준으로 채점했다. 가설은 LLM이 자유 문구로 쓰기 때문에 정답의 고정 문구와 맞출 수 없어서 뺐다. `RESULT_llm_extractor.json`.

| 세트 | LLM 정밀도 / 재현율 | 규칙 정밀도 / 재현율 |
|---|---|---|
| heldout3 | 0.544 / 0.807 | 0.870 / 0.645 |
| heldout4 | 0.537 / 0.806 | 0.720 / 0.500 |
| heldout5 | 0.466 / 0.850 | 0.708 / 0.425 |

LLM은 재현율이 훨씬 높고 정밀도가 낮다. 정답셋이 "본문에 나온 장소·도구·프로젝트·사람"만 적게 되어 있어서 LLM이 추가로 뽑는 음식, 동행, 행동 같은 것이 오류로 집계되었을 가능성이 있다. 어느 쪽이 맞는지는 오류 목록을 사람이 봐야 한다.
