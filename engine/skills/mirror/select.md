# Select relevant understanding and source experience

Load when personal understanding could affect the current help, or a meaningful new experience could change it. Use the same host reasoning and existing store. Input: current request, scope and episode. Output: relevant cards, source IDs with roles/chronology, and any material evidence gap; do not patch during selection.

1. For a reply, start with `{"op":"index"}`. Read the active statements across scopes and shortlist cards worth inspecting for a live choice, question or deliverable. A similar decision in a different domain can justify inspection even when transfer is uncertain. A topic match alone is insufficient. Inspection does not authorize forwarding. If no card could help, pass no Mirror context. The catalogue is for selection only.
2. Before forwarding any selected statement, inspect its full card internally via `context` and `include_ids`. Check its reason, conditions and material counterevidence against this request. For handoff to a reply generator, request `{"op":"deliver","expected_revision":7,"selections":[{"id":"card-id"}]}`, using the revision you actually read. Each selected statement retains its kind and scope. If a reason, exception or limit matters here, include its **exact, self-contained excerpt** in the selection under `reason` or `conditions`. Preserve who chose or offered what, what it enabled, negations and uncertainty. Omit the card if its statement is episode-specific or would mislead without more context than is useful. Forward only the resulting cards; an empty list needs no injection. On a stale selection, reselect against the current index. A host doing its own selection in the same conversation has already seen the tool results; this handoff limits the context of a separate answer generator.

   For formation or verification, inspect other-scope `context.candidates` even when in-scope cards exist. Read the complete affected cards and retrieve source events with `{"op":"events","ids":["source-id"]}` or `{"op":"events","episode":"episode-id"}`. Keep speaker roles, order, the original task and actual answer. Preserve source records verbatim and link translations separately. Never reconstruct suppressed sources.
3. Observe choices, corrections, accepted results and meaningful experiences. Append the actual exchange with stable event IDs and one episode ID, keeping the original answer before a correction. A plain factual lookup, formatting edit or repetition need not change personal understanding. A material mismatch, new reason, preference boundary, anticipated consequence or contrary experience may justify formation/revision, including still liking something while changing the choice. Task state alone is not a personal pattern.
4. On meaningful new evidence, read the **complete affected active card**, not just its index statement or a previous summary: statement, kind, reason, conditions, support and contrary sources. Compare the new episode with its existing scope and time limits. Before applying dated plans/offers, resolve whether they still apply to the current episode; expiration is not evidence that an activity occurred. Distinguish historical availability from a new explicit commitment. Send the full card and triggering sources to formation/check so obsolete conditions can be replaced, not left active beside an appended correction. On immediate feedback, select the affected evidence and revise locally before helping with the present task; do not reinterpret the whole person or wait for background analysis. At a meaningful task boundary/transition, request `prepare` for the episode. If `noop` is true, skip reflection. Otherwise use its unreviewed events alongside relevant earlier evidence. Ordinary requests can expose a gap too; no negative-feedback requirement, separate classifier, fixed interval or mandatory per-turn call.

Current requests take priority. Apply every relevant already-established criterion in the first answer without re-asking established allowances or boundaries. Unrelated cards need not be used. A natural task clarification may resolve an unestablished practical boundary; do not interview for hidden motives.

## Resolve material evidence gaps iteratively

For broad historical formation, compare a few materially different promising choice/correction clusters from the initial source inventory before spending most of the existing budget deepening one. Prioritize informative contrasts and the functions of choices over frequency alone. Record the chosen focus and materially promising unexamined clusters in the existing trace. This does not apply to current-domain help and requires no exhaustive coverage, fixed quota or forced cross-domain synthesis; use the same host and budget without extra models, calls or schemas.

Start with the available episode or explicit self-report and a provisional candidate from [form](form.md). Identify the unresolved evidence question that could change the candidate. Within the agreed budget, retrieve relevant support **and** contrasting cases or conditions using `context` candidates/`include_ids`, `events`, `prepare`, and other already authorized host source access. Examine behavior, desired end, prerequisites/transitions, and when the behavior changes or becomes unnecessary. Look for earlier goals, stakes, options, costs/consequences and original assistant premises where they resolve the mismatch. Do not search only to confirm the candidate or require an exhaustive checklist.

Return the new evidence to formation and [check/revise](check-revise.md). Repeat only if accessible new evidence could resolve a material gap; stop when none is accessible, the budget is exhausted, or the explanation suffices for present help. Preserve unresolved alternatives and uncertainty. Missing evidence does not force a user question. This procedure installs no semantic archive search and establishes no quality result.
